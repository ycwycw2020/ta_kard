# 更换服务器与网络地址 · 塔卫牌局 1.0

本次只增加同一测试链内的连接切换，不创建新链，不清空身份、卡牌、存档或区块数据。链 ID 为 20260926，创世区块为 0x27c9903f7a3c87bc6028d8a19769dd5920f96cf45492a3ae4f083e171f6ce596。

## 已安装设备如何获得新入口

解压本次新版对应系统安装包，再运行 Install.cmd 或 Install.sh，选择原安装目录和当前服务器 IP。安装器会保留节点身份和链数据并更新维护工具。若节点此前由手动命令或 systemd 启动，先停止对应原服务。不要删除节点目录，不需要重装系统。

## 原服务器只是 WLAN IPv4 变化

填写服务器的 WLAN **IPv4 地址**，不是“默认网关”。主机本次实测地址为 10.195.244.225；日后以主机 ipconfig 显示的实际地址为准。校园网或 VPN 必须允许两台电脑相互访问对应的 P2P TCP 端口。

Windows：打开已安装节点目录，双击 **Change-Server.cmd**，修改服务器 IPv4，点击“连接并验证”。公开连接文件留空即可。

Linux：进入已安装节点目录，运行：

```bash
bash ./change-server.sh --server 10.195.244.225
```

也可以直接运行 `bash ./change-server.sh`，按提示输入新地址。

## 更换为另一台同链节点

不同节点有不同公钥，仅修改 IP 无法把旧公钥变成新节点身份。请先在目标节点运行 Export-Server.cmd（Windows）或下面的命令（Linux），导出公开连接文件：

```bash
bash ./export-server.sh --server 目标节点IPv4 --output ./server-connection.json
```

目标必须已运行并属于同一条链。Windows 主服务器也提供 `D:\card_endfiled\Export-Server.cmd`。文件只包含 IPv4、P2P 端口、公钥、链 ID 和创世哈希，可以交给接入方；不含私钥。导出时不会覆盖已有文件。

Windows 接入方：在 Change-Server.cmd 窗口中选择这份 JSON，确认它带入的地址后连接。

Linux 接入方：

```bash
bash ./change-server.sh --server-profile ./server-connection.json
```

如果连接文件内地址也已过期，可额外添加 `--server 新IPv4`，覆盖文件中的地址。自定义 P2P 端口可用 `--server-port 端口`。不同链的连接文件会被拒绝，不会为它建立新链。

## 工具如何判断成功

先验证 TCP 可达，再备份配置并重启本节点；随后检查同一创世区块、至少一个对端和区块高度增长。60 秒内未确认区块增长会恢复原配置；原来运行的节点会重新启动。服务器暂停出块时也可能触发恢复，应先恢复链运行再重试。

`verified: true` 表示该连接已提供本链新增区块，不代表历史区块已经全部追平。仍可用 Status-Node.cmd / `bash status-node.sh` 检查同步进度。成功记录位于 last-server-change.json，旧配置位于 backups。node/key 和 node/data 不会被清空。

## 网页与数据库

这个入口切换区块链的 P2P 连接。游戏数据库仍由 Windows 游戏主机保存。若游戏主机地址也改变，网页所用 SSH 隧道的目标地址也要跟着修改；仅切换到某个同步节点并不会让它自动提供游戏网页和数据库。卡面继续从同一个游戏网页服务加载，无需每台节点单独复制插画。

## 本次复查中尚需管理员处理的一项

原主机防火墙规则 `Talos external Windows peer` 仍绑定旧本机 IP 10.192.253.144，原远端限定为 10.193.34.245。自动更新被 Windows 拒绝访问，尚未修改。请在主服务器以管理员身份打开 PowerShell 后运行发行目录中的脚本：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'D:\塔卫牌局_v1.0\修复外部节点防火墙.ps1' -PrimaryIP '10.195.244.225' -ExtraIP '10.193.34.245'
```

脚本只更新现有这条规则的本地地址，保留远端限制和端口。若两台电脑的地址再次变化，应填写实际地址。该脚本不会放开整个网络的防火墙。修复后由外部电脑测试 `Test-NetConnection 10.195.244.225 -Port 30303`，再运行更换服务器入口。

## 全新电脑的依赖下载

安装器支持自动准备 Node.js、Java、Besu。本次在 Windows 和 Ubuntu 上实测了独立安装目录、自动识别、已有运行环境复用、真实同步、升级和切换。测试环境访问 Node.js 正常，但访问 GitHub/Besu/Adoptium 下载地址超时，因此不能保证受当前网络限制的全新电脑首次联网下载必定成功。完整发行包提供公开运行环境归档，也可以用 `-RuntimePath`（Windows）或 `--runtime`（Linux）指定已经解压的 Java/Besu 目录。
