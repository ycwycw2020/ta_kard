# 塔卫牌项目介绍与课程报告

作者：杨诚伟。个人独立完成的区块链课程项目；采用开源依赖与 AI 辅助美术生产。项目角色及美术原型来自鹰角网络《明日方舟：终末地》，未取得官方授权，只用于非商业学习交流。

## 问题与方案

传统游戏的卡牌归属、挂售成交和战斗结算通常完全依赖应用数据库。项目选择低频回合制卡牌场景，展示怎样把适合核验的部分放入以太坊兼容合约，同时把图片、会话、配装与查询缓存保留在传统后端。

产品包括角色配装、4 对 4 前后排对战、PVP 与 AI、卡面铸造与收藏、独立编号与测试 ETH 商城。外观和数值分开，稀有卡面不会直接带来战斗数值优势。

## 技术实现

前端使用原生 HTML/CSS/JavaScript 与 ethers；WebGL 实现部分卡面的呼吸和风动。后端使用 Node.js、PostgreSQL，索引器将确认事件写入可查询表。Windows 保存唯一应用数据库，两台 Ubuntu 与 Windows 各运行一个 Besu QBFT 验证者，共享同一条 Chain ID 20260926 的测试链。

Solidity 0.8.30 实现三类业务合约：TalosCards/ERC-1155 处理测试铸造凭证、额度、承诺揭示和奖励；TalosCardItems/ERC-721 处理独立资产和市场；TalosBattle 自定义状态机处理行动规则、伤害和胜负。公开部署地址见 CONTRACTS.md，字节码与 ABI 在 build。

当前保留 16 费与 20 费两版战斗合约，属于两个实例而非代理升级。前后端按所选模式为新房间选择地址，已有对局保持原规则。它们共用同一 NFT 合约，不必重新铸造或清空资产。

## 区块链的实际收益

资产所有权、转赠与交易规则由合约约束，查询数据库出错不直接改变链上所有者。战斗行动需要钱包签名，合约验证参与者与递增序号，防止通过改网页直接伪造伤害或跳过回合。事件、交易回执与状态哈希可用于独立核对，适合课堂演示“提交—共识—执行—可验证结果”的完整路径。

承诺揭示避免种子在请求后随意替换；拒绝采样减少模映射偏差；到期退款避免请求永久悬挂。16 位编号适合展示和录入，真正资产身份仍含链与合约域，校验码不被夸大为加密认证。商城携带挂单版本并采用卖家提取收益，降低陈旧界面与外部支付回调对购买流程的影响。

## 可交付成果

- 前端、后端、数据库结构、三类合约源码与构建产物；旧 16 费归档、20 费现行版本与公开部署记录。
- Windows/Linux 分开的现有链自适应安装入口，同链更换服务器及 IPv4 配置入口。
- 32 名角色、306 张静态卡面；170 普通、100 精美、36 超精美。庄方宜与诀各 18 张；6 张超精美带呼吸与风动。
- 2160×3840 超分辨率交付图、原始生成图、轻量展示图与处理元数据；不将超分结果表述为原生 4K。
- 项目介绍、架构、合约说明、启动/节点说明与可编辑答辩 PPT（单独发行附件）。

## 验证情况与边界

项目历史记录包含旧版对战的合约差分验证和真实链上完整对局。新 20 费版本已完成部署字节码核对、后端模式边界、界面切换、同一真实链上的只读 createMatch 初始化模拟；确认 20 费队伍可进入新版且被旧版拒绝。**这不等于已对新版所有队伍完成真实完整 PVP 对局验证，也不等于独立安全审计。** 本次发布打包检查只核对文件、许可、密钥排除、离线测试和资源校验，不新增玩家、房间或测试链。

仍预留 576 个卡面差分槽位，目前实际产出 306，不能声称所有角色全部差分已画完。新的网络或陌生系统下的自适应安装仍取决于防火墙、下载站点、权限和服务器可达性。

## 限制与后续方向

项目不是完全去中心化：三个验证者、API、AI、奖励签名与种子服务均由同一管理者控制。公开牌局没有隐藏信息保护，图片也未通过分布式存储保证永久可用。签名服务、数据恢复、随机性治理、独立验证者、超时退出和重放工具仍可改进。

链上运算与存储存在开销；即使本测试链零 gas 价格，也不代表计算免费。建议把此方案定位为区块链与传统后端混合架构的课程实践，不将其宣传为高频动作游戏通用方案或绝对防作弊系统。
